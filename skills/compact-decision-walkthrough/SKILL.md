# Compact Decision Walkthrough

## Overview

- Help the user make one informed decision at a time in an implementation plan.
- Read the full source and the code needed to understand it.
- Present only one item at a time. 
- Only reference other items if relevant for current item.

## Decision Card

The answer should look roughly like this. Keep it short and relevant.

```markdown
### <Item>

**Problem:** What is wrong or unclear, in plain language.

**Consequences:** What changes if it is fixed, skipped, or removed. Pros and cons of doing this. Show code if natural.

**Options:** Show multiple options only if there is more than one option.

**Recommendation:** A clear choice and why it fits the user's constraints.

**Decision:** Approve, adjust, skip, or ask for more detail?
```
